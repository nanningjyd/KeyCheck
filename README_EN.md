# KeyCheck · LLM API Key Availability Tester

A **pure-frontend, zero-backend** web tool to batch-test the availability of LLM provider API keys and list their models, translating cryptic errors into plain language. Features automatic vendor detection, batch credential parsing, model dropdowns, continuous chat, and an optional Cloudflare proxy to bypass browser CORS limits.

> This project **ships no secrets**. All keys are pasted by you in the page and, for local testing, only live in browser memory.

---

## Features

- **Batch parsing**: paste multiple `endpoint / key / model` groups; auto-chunks, inherits URL, pairs key with model.
- **Auto vendor detection**: probes `/v1/models` response shape to decide OpenAI-compatible vs Anthropic-native — no guessing by domain.
- **Human-readable results**: success/failure/rate-limit are translated to plain text; no raw JSON, status codes, or links are shown. Latency is simplified to *fast / normal / slow*.
- **Model dropdown**: once models are fetched, the model field becomes a selectable dropdown; the chat dialog defaults to the selected model.
- **Continuous chat**: per-row chat button opens an isolated dialog carrying full history.
- **Free-model probe** (freetokenfaucet.com): auto scrapes today's free models from the homepage → full `/v1/models` → probes each with `max_tokens:1` and reads remaining quota, no login required.
- **Dark / light** themes (dark by default, persisted to localStorage).
- **CORS four-option panel (collapsible)**: A browser extension / B launch-with-flags / C public proxy / D local or cloud proxy (Cloudflare Workers).

## Local usage

1. Open `llm-key-tester.html` in your local browser (not an online preview, or CORS-proxy features will be limited).
2. Paste your `endpoint + key + model`, click **Parse**.
3. Click **Test All** and read the results.
4. If the browser blocks with CORS, expand the CORS panel at the bottom:
   - **Option D (local, recommended)**: run `node proxy.js` in this folder, keep the window open, then pick D + Local.
   - **Option D (cloud)**: after deploying to Cloudflare (below), pick D + Cloudflare Workers — the address is pre-filled.

## Deploy to Cloudflare (domain KeyCheck.hhxx.eu.org + proxy Worker)

This repo ships a **Cloudflare Worker** (`worker/worker.js`) that, on the same domain:
- `/` serves the tool page
- `/proxy?url=<target>` acts as a CORS reverse proxy
- `/health` is used by the tool for health checks

### One-click deploy (recommended)

On your own machine (not a sandbox), from the repo root:

```bash
# 1) Prerequisites
npm install -g wrangler
git config --global user.name  "Your Name"
git config --global user.email "you@example.com"

# 2) Cloudflare env vars (from the Cloudflare dashboard)
export CF_ACCOUNT_ID=your-account-id
export CF_ZONE_ID=zone-id-of-hhxx.eu.org

# 3) Run the deploy script (reads the Cloudflare global key from 备忘key.txt; never prints or commits it)
node deploy.mjs
```

Prerequisites:
- `node 18+`, `git`, `gh` (GitHub CLI), and `wrangler` installed locally.
- Your `备忘key.txt` at the repo root, format: line 1 = GitHub PAT (`ghp_…`), line 3 = Cloudflare Global API Key (40 hex), line 6 = DNS edit token. **This file is excluded by `.gitignore` and never pushed to GitHub.**
- `hhxx.eu.org` is already added to the Cloudflare account and its NS points to Cloudflare.

The script automatically: inits Git → creates the public repo `KeyCheck` and pushes → creates the `KeyCheck.hhxx.eu.org` DNS record → deploys the Worker.

### Manual deploy

1. **GitHub**: `git init && git add . && git commit -m init && gh repo create KeyCheck --public --source . --remote origin --push`
2. **Worker**: `cd worker && wrangler deploy` (needs `CLOUDFLARE_API_KEY` + `CLOUDFLARE_EMAIL`, or run `wrangler login`).
3. **DNS**: in Cloudflare add a CNAME `keycheck` for `hhxx.eu.org`, enable proxy (orange cloud), and add a Worker route `keycheck.hhxx.eu.org/*`.

## Security & privacy

- This tool **does not collect or store any key**. For local testing, keys only exist in browser memory for the request; in cloud-proxy mode, requests pass through Cloudflare and your Worker (visible to the platform), so use **your own account**, self-host, and **do not publicly share the proxy URL**.
- The repository **contains no real secrets**; `备忘key.txt`, `.workbuddy/`, etc. are all excluded by `.gitignore`.
- The public repo contains only the tool code and docs. Verify no personal secrets are committed before pushing.

## Disclaimer

This tool is for personal testing of API keys you are legitimately authorized to use. Comply with each provider's terms of service; do not use it for any violation.
